# AVD Terraform Deployment

Deploys an Azure Virtual Desktop environment in **centralus**:

- 1x **Pooled** host pool (multi-session, breadth-first, max 10 sessions/host)
  - **SSO enabled** for Entra ID joined hosts (`enablerdsaadauth:i:1`, `targetisaadjoined:i:1`)
  - Sensible default RDP redirections (clipboard, printers, drives, USB, camera, audio)
- 1x Workspace
- 1x **RemoteApp** Application Group with 3 published apps:
  - Notepad (`notepad.exe`)
  - Microsoft Edge (`msedge.exe`)
  - Remote Desktop (`mstsc.exe`)
- 2x Session hosts: **Windows 11 25H2 multi-session, no Office** (`Standard_D2s_v5`)
- **Microsoft Entra ID join** (AADLoginForWindows extension)
- AVD DSC agent registration to the host pool
- New VNet + Subnet (`10.50.1.0/24`) + NSG
- **Key Vault** (RBAC mode) storing local admin username/password and host pool registration token

## Files

| File | Purpose |
|------|---------|
| `providers.tf` | Provider versions + features (azurerm ~> 4, azuread ~> 3, random, time) |
| `variables.tf` | All inputs |
| `main.tf`      | RG, network, KV, host pool, workspace, app group, RemoteApps, session hosts, RBAC |
| `outputs.tf`   | Useful outputs (KV name, hosts, app group, etc.) |
| `terraform.tfvars.example` | Sample variables file |

## Requirements

- Terraform **>= 1.6**
- Azure CLI logged in to the target tenant (`az login`)
- Deploying principal: **Owner** (or **Contributor** + **User Access Administrator**) on the subscription / RG — required because role assignments are created (`Desktop Virtualization User`, `Virtual Machine User Login`, `Key Vault Administrator`).

## Usage

```powershell
cd AVD/RemoteApps-Terraform
Copy-Item terraform.tfvars.example terraform.tfvars
# Edit terraform.tfvars: set subscription_id and avd_user_object_ids

az login
terraform init
terraform plan  -out tfplan
terraform apply tfplan
```

## Retrieving the local admin password after apply

```powershell
$kv = terraform output -raw key_vault_name
az keyvault secret show --vault-name $kv --name avd-local-admin-password --query value -o tsv
```

## Enabling Single Sign-On (one-time tenant prerequisite)

Setting `enablerdsaadauth:i:1` on the host pool (already configured in `main.tf`) is **necessary but not sufficient**. SSO on Entra-joined hosts also requires you to allow the AVD client app to use the session host as a target resource. This is a one-time tenant op:

```powershell
$msrdcAppId = "a85cf173-4192-42f8-81fa-777a763e6e2c"  # Microsoft Remote Desktop client
$winCloudId = "270efc09-cd0d-444b-a71f-39af4910ec45"  # Windows Cloud Login

Install-Module Microsoft.Graph -Scope CurrentUser
Connect-MgGraph -Scopes "Application.Read.All","Application.ReadWrite.All"

foreach ($id in @($msrdcAppId,$winCloudId)) {
  if (-not (Get-MgServicePrincipal -Filter "AppId eq '$id'")) {
    New-MgServicePrincipal -AppId $id
  }
}
```

Then enable RDP SSO targeting on the Microsoft Remote Desktop service principal (see Microsoft Learn: *Configure single sign-on for Azure Virtual Desktop using Microsoft Entra authentication*).

## Tear down

```powershell
terraform destroy
# If you plan to reuse the key vault name, purge the soft-deleted vault:
az keyvault purge --name <kv-name> --location centralus
```

## Notes / Assumptions

- `image_sku = "win11-25h2-avd"` — the Win 11 25H2 multi-session **no-Office** marketplace SKU. If your tenant/region does not yet expose 25H2, change to `win11-24h2-avd` in `terraform.tfvars`.
- Entra ID join requires assigning the **Virtual Machine User Login** role to AVD users on the VM/RG scope (handled automatically for `avd_user_object_ids`).
- The host pool registration token is set with a 24h expiry; the `lifecycle.ignore_changes` keeps Terraform from re-rotating it on every plan.
- No public IPs on session hosts. Outbound internet is via default Azure outbound (sufficient for AVD agent download / WVD service tags). Add a firewall/NAT gateway if your security posture requires it.
- Key Vault uses RBAC (no access policies). The deploying principal is granted `Key Vault Administrator` so secrets can be written during the same apply (with a 60s `time_sleep` to allow RBAC propagation).
- Local admin password is generated by Terraform (`random_password`) and stored only in Azure Key Vault. It is never written to outputs.
